## 📖 Sobre o projeto

Este projeto é um **roadmap de aprendizado para Java Backend**, criado para organizar uma evolução baseada em competência, prática e evidências — e não apenas em uma lista de tecnologias para estudar.

A trilha é **Backend-first**:

- **80–90% Backend** — foco principal em Java, Spring Boot, bancos de dados, APIs, testes, segurança, Docker e práticas de produção.
- **10–20% Frontend** — trilha complementar e opcional, que nunca bloqueia a evolução do Backend.
- **Gates de competência** — o avanço depende da capacidade de explicar, implementar, testar, corrigir e aplicar o conhecimento.
- **Projetos progressivos** — cada etapa transforma conhecimento em algo concreto para construir e comprovar.
- **Evidências** — um item estudado não é automaticamente um item dominado.

> **Princípio central:** não preciso saber tudo. Preciso conseguir fazer.

---

## 🎯 Objetivo

Preparar uma base sólida para buscar **estágio no fim de 2026 / início de 2027** e continuar a evolução até o nível de **Backend Java Júnior**, sem transformar o roadmap em uma corrida para acumular frameworks.

A progressão segue:

**Competência → Prática → Projeto → Evidência → Experiência → Portfólio → Certificação**

Certificações e tecnologias avançadas entram como diferenciais, não como substitutos da capacidade prática.

## 🗺️ Visão geral

O roadmap é dividido em Gates. Cada Gate representa um conjunto de competências que precisa ser desenvolvido antes de avançar.

| Gate | Foco | Resultado esperado |
| --- | --- | --- |
| **G0** | Fundamentos Java | Programar em Java sem depender de tutorial |
| **G1** | Backend Foundation | Construir uma API backend funcional |
| **G2** | Gate de Estágio | Ter base suficiente para começar a buscar estágio |
| **G3** | Backend Júnior | Construir, testar, documentar e operar um backend profissional |
| **G4** | Avançado | Aprofundar arquitetura, concorrência, mensageria, cache e observabilidade |
| **F1** | Frontend Complementar | Ter noções suficientes para consumir e integrar APIs |

### Estados dos Gates

- 🔴 **Não pronto** — ainda existem lacunas relevantes.
- 🟡 **Pronto para avançar** — critérios mínimos atingidos, mas ainda pode haver consolidação.
- 🟢 **Gate concluído** — critérios e evidências exigidas foram atingidos.

Os thresholds atuais são definidos diretamente no `index.html`.

## 🧱 Projetos

Os projetos formam uma linha contínua de evolução em vez de projetos isolados:

```text
BiblioTrack
    ↓
TaskFlow
    ↓
TaskFlow — versão profissional
    ↓
TaskFlow em produção
    ↓
Capstone
```

| Projeto | Gate | Objetivo |
| --- | --- | --- |
| **BiblioTrack** | G0 | Aplicar fundamentos Java em uma aplicação de console |
| **TaskFlow** | G1 | Construir uma API backend com persistência |
| **TaskFlow — versão profissional** | G2 | Evoluir a API com autenticação, Docker e práticas profissionais |
| **TaskFlow em produção** | G3 | Levar o backend para um cenário próximo de produção |
| **Capstone** | G4 | Aprofundar um conceito avançado com um projeto de maior complexidade |

Um projeto só conta como evidência forte quando está **COMPROVADO** e possui um link verificável, como commit, PR, API ou deploy.

## 📊 Como o progresso funciona

O dashboard salva o progresso diretamente no navegador usando `localStorage`.

### Estados de aprendizagem

O roadmap diferencia três situações importantes:

- 📚 **Estudado** — o conteúdo foi visto ou revisado.
- 🧪 **Praticado / Aplicado** — houve exercício, implementação ou aplicação real.
- 📝 **Comprovado** — existe evidência suficiente para sustentar que a competência foi demonstrada.

Isso evita que marcar um checkbox seja confundido com domínio real.

### Histórico de estudo

O dashboard também mantém um histórico local de atividades recentes para alimentar o fluxo de estudo com IA:

- **Estudado recentemente** — atividades dos últimos 14 dias.
- **Praticado / aplicado recentemente** — exercícios, práticas e aplicações registradas.
- **Última revisão** — classificação dos itens como consolidado, precisa de reforço ou não comprovado.
- **Sequência (🔥)** — dias consecutivos com pelo menos um item registrado.

O botão **“Copiar status para IA”** reúne essas informações em um contexto pronto para usar em sessões de estudo e revisão.

> O histórico é local ao navegador. Ele não é sincronizado automaticamente com o GitHub.

## 🤖 IA como ferramenta

O roadmap foi estruturado para usar IA como acelerador sem terceirizar o raciocínio.

### A IA pode ajudar com

- Boilerplate repetitivo.
- Getters, DTOs e configurações mecânicas.
- Explicação de mensagens de erro.
- Rascunhos de documentação.
- Massa de dados para testes.
- Sugestões de refatoração para avaliação.

### A competência precisa continuar sendo sua

- Explicar seu próprio código.
- Escolher entre soluções e justificar a decisão.
- Debugar sem simplesmente colar o erro inteiro em uma IA.
- Explicar decisões de arquitetura.
- Resolver o núcleo do problema.

> **Use IA para acelerar o trabalho nas bordas, não para pensar no centro por você.**

## 🧑‍💻 Executar localmente

O projeto é uma página estática. Não há framework, dependências de Node ou etapa de build.

### Opção 1 — abrir diretamente

Baixe ou clone o repositório e abra `index.html` no navegador.

```bash
git clone https://github.com/gustavoh-silva/roadmap-backend-java-junior.git
cd roadmap-backend-java-junior
```

Depois, abra `index.html`.

### Opção 2 — servidor local

Qualquer servidor HTTP estático pode ser utilizado. Por exemplo, com Python:

```bash
python -m http.server 8000
```

Acesse `http://localhost:8000`.

O GitHub Projects pode ser usado como uma camada opcional de organização das tarefas.


O board e o dashboard possuem papéis diferentes:

## 🧠 Princípios do roadmap

### 1. Competência antes de calendário

As datas são referências de ritmo. Não existe avanço automático só porque uma semana passou.

### 2. Prática antes de acumular conteúdo

Conhecer a teoria é necessário, mas implementar, testar e corrigir é o que transforma conhecimento em competência.

### 3. Evidência antes de declarar domínio

Checkbox marcado não é prova. Projetos, commits, PRs, APIs, testes e deploys tornam o progresso verificável.

### 4. Backend primeiro

O foco principal é empregabilidade em Java Backend. O Frontend existe para complementar essa capacidade, não para desviá-la.

### 5. Complexidade progressiva

Tecnologias avançadas entram depois que a base estiver consolidada. O objetivo não é estudar tudo ao mesmo tempo.

### 6. Anti-tutorial-hell

O roadmap privilegia situações em que é necessário pesquisar, raciocinar, implementar e resolver problemas reais.

## 🔄 Evolução do roadmap

A versão atual é a **V3**. Entre as principais mudanças em relação à V2 estão:

- Projetos com continuidade entre os Gates.
- Maven no G0 e Flyway no G1.
- Documentação profissional de API como competência do G3.
- Perguntas de entrevista por Gate.
- Diretrizes explícitas para uso de IA.
- Diferenciação entre indicador de prática e prova de competência.
- Dashboard separado para Backend Core, G2 Estágio e Frontend.
- Histórico local de estudo, prática e revisão.

O roadmap deve ser revisado periodicamente porque versões de frameworks, ferramentas e expectativas do mercado mudam.
